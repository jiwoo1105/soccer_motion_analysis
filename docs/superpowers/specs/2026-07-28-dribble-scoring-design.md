## 1. 목표

축구 인-인 드리블 영상 1편을 입력하면 세 지표를 각 10점으로 채점하고
가중 평균한 총점 10점을 출력한다.

| 지표 | 의미 |
|---|---|
| 헤드업 | 터치 순간 머리 각도의 변화폭 |
| 상체각도 | 무릎-엉덩이-어깨 각도 (숙인 정도) |
| 어깨-골반 | 어깨 진폭 / 골반 진폭 비율 (골반 주도 여부) |

대상은 `input/in_in/` 13편으로 한정한다. `input/in_out/` 16편은 이번 범위 밖이다.

## 2. 전제 — 재검증하지 않는다

선행 분석에서 확정된 사실이다. 근거는 §1의 두 문서에 있다.

1. **이상치 판별은 Hampel.** 전후 ±5프레임 중앙값 대비 10° 초과 시 이상치.
   avg / lastvalid / old 방식은 각각 기각됐다.
2. **어깨 진폭 단독은 점수대와 무관하다** (Pearson −0.21). 단독 지표로 쓰지 않는다.
3. **어깨와 골반은 상관 0.89~0.99, 위상차 0프레임** — 사실상 같은 신호다.
   따로 점수화하면 중복이므로 비율이라는 관계 지표로 통합한다.
4. **위상차(교차상관 lag)는 쓰지 않는다.** Spearman +0.91은 11개 중 8개가
   동점인 통계적 착시다 (Pearson +0.17).
5. 파일명 앞자리가 사람이 매긴 점수대다 (`인,인 7-2.MOV` → 7점대).
   `기준1`, `기준2`는 정답 템플릿이다.

## 3. 아키텍처

```
영상 1편
  ├─ 포즈 추출 (MediaPipe, model_complexity=2)
  ├─ 공 추적 (YOLOv8 초기검출 → SAM2 전체추적) → 터치 감지
  ├─ 터치 유효성 필터
  │
  ├─ [지표1] 헤드업     : 유효 터치 ±8f, head angle mean_range
  ├─ [지표2] 상체각도   : 전체 프레임, 무릎-엉덩이-어깨 각 평균
  └─ [지표3] 어깨-골반  : 유효 터치 ±8f, 어깨진폭/골반진폭 비율
       ↓
  공통 점수식 → 각 0~10점 → 가중 평균 → 총점 0~10점 + 신뢰도 플래그
```

### 모듈 구성

기존 분석 파일(`compare_spike_methods.py`, `extract_rotation_score.py`,
`analyze_score_tiers.py`)은 **근거 자료이므로 덮어쓰지 않는다.** 전부 새 모듈이다.

| 파일 | 역할 | 의존 |
|---|---|---|
| `scoring/raw_metrics.py` | 세 지표의 원시값 추출 | core, analysis |
| `scoring/touch_filter.py` | 터치 유효성 판정 | — |
| `scoring/calibration.py` | 기준1·2에서 앵커 산출 → `calibration.json` | raw_metrics |
| `scoring/score_mapper.py` | 원시값 → 10점 변환 | calibration.json |
| `score_video.py` | CLI 엔트리포인트 (영상 1편 → 점수) | 위 전부 |
| `validate_scoring.py` | 13편 검증 (표 + 상관 + 단조성) | 위 전부 |
| `make_panorama.py` | 3영상 비교 그림 | 위 전부 |

각 모듈은 독립 실행 가능하고, 상위 모듈은 하위 모듈의 내부를 모른다.
`score_mapper`는 원시값이 어떻게 만들어졌는지 알 필요가 없고,
`raw_metrics`는 점수 매핑을 알 필요가 없다.

실행 환경은 **python3.9** 다. 다른 버전에는 mediapipe가 없다.

## 4. 공통 점수식

세 지표 모두 같은 식을 쓴다.

```python
score = clamp(0, 10, (TAU - abs(x - opt)) / TAU * 10)
```

- `opt` = **기준1·기준2의 해당 지표 평균**. 하드코딩하지 않고 `calibration.json`에서 로드한다.
- `TAU` = 허용 편차. **`2 × std(13편 원시값)`으로 정의한다.**

세 지표를 같은 식으로 통일하는 이유는 두 가지다.
첫째, "값이 클수록 좋은가 작을수록 좋은가"라는 방향성 논쟁이 사라진다.
실제로 `analysis/head_pose_analyzer.py:186-189`의 주석("작을수록 좋음")과
프로젝트 메모리("클수록 좋음")가 서로 충돌하고 있었는데, 앵커 방식에서는
기준영상 값이 최적이므로 이 충돌 자체가 성립하지 않는다.
둘째, "왜 이 지표만 다르게 계산했나"라는 질문을 받지 않는다.

### TAU를 2σ로 정하는 근거

상관계수가 올라갈 때까지 τ를 돌리는 것은 n=11에서 과적합이다.
그래서 라벨과 무관한 규칙을 미리 고정한다. 2σ는 "이 동작 분포에서 극단값"이라는
통계적 의미가 있고, 라벨을 전혀 보지 않고 계산된다.

어깨-골반 비율에 대해서는 근거 문서가 초기값 0.40을 제시했으므로,
검증 단계에서 **2σ 값과 0.40을 나란히 보고**한다. 둘 중 상관이 높은 쪽을
고르는 것은 튜닝이므로 하지 않는다. 채택본은 2σ이고, 0.40은 참고값이다.

## 5. 지표별 정의

| 지표 | 원시값 | 측정 구간 | 신호원 |
|---|---|---|---|
| 헤드업 | `touch_window_mean_range` (°) | 유효 터치 ±8f | world_landmarks Y축 |
| 상체각도 | `trunk mean_angle` (°) | 전체 프레임 | world_landmarks |
| 어깨-골반 | `어깨진폭 / 골반진폭` | 유효 터치 ±8f | **2D 폭** |

### 5.1 헤드업

`analysis/head_pose_analyzer.py`의 `_compute_touch_window(window=8)`를 재사용한다.
어깨 중앙 → 눈 중앙 벡터와 수직축의 각도를 구하고, 각 터치 윈도우의
(최대 − 최소)를 모든 유효 터치에 대해 평균한 값이 원시값이다.

world_landmarks의 Y축만 쓰므로 X 노이즈 문제의 영향을 받지 않는다.

### 5.2 상체각도

`analysis/trunk_pose_analyzer.py`의 `calculate_trunk_angle`을 재사용한다.
무릎-엉덩이-어깨 각도를 좌우 평균하고, 전체 프레임에 대해 평균한다.
터치와 무관한 지표이므로 터치 필터의 영향을 받지 않는다.

### 5.3 어깨-골반

**Phase 1(§7)의 신호원 전환을 먼저 통과해야 한다.**

현재 회전각은 `atan2(vz, vx)`로 world landmark의 z축을 쓰는데, z는 촬영 각도에
따라 눌린다(8점대 두 영상이 어깨·골반 모두 최저권으로 나온 원인). 2D 어깨/골반 폭
기반으로 교체한다. `analyze_score_tiers.py`의 `extract_all()`에 이미
`sh_w2d`, `pe_w2d` (`abs(il[12].x - il[11].x) * w_frame`) 추출 코드가 있으므로 재사용한다.

2D 폭 → 회전각 변환식은 "폭이 최대일 때 정면 0°, 좁아질수록 회전이 크다"는
관계로 정하고 근거를 주석으로 남긴다.

처리 순서는 유지한다:

```
각도 → unwrap → Hampel 이상치 제거 → 선형 보간 → savgol(41,2)
     → 드리프트 제거(savgol 81,2) → find_peaks(distance=10, prominence=3)
     → 연속 극값 차의 평균 = 진폭
```

**이상치 제거를 드리프트 제거보다 먼저** 해야 한다. 스파이크가 남은 채로
baseline을 뽑으면 주변까지 오염된다.

Hampel 적용 시 두 가지를 보강한다:

```python
# ① 경계효과 제거 — 창이 잘리는 앞뒤 5프레임은 판정에서 제외
bad[:5] = False
bad[-5:] = False

# ② Hampel 한계 초과 경고 — 창 11개 중 과반(6개)이 오염되면 중앙값이 넘어가 놓친다
#    6프레임 이상 연속 플래그 구간이 있으면 경고를 출력한다
```

비율의 물리적 의미: 1.0에 가깝거나 넘으면 어깨가 골반만큼 돌았다는 뜻이고,
이는 상체로 몸을 끌고 가는 것(골반 주도 실패)이다. z축 기준 측정에서
비율 ≥ 1.0인 영상은 3점대 2편(1.20, 1.00)뿐이었다.

## 6. 터치 유효성 필터

터치 하나가 유효하려면 아래를 **전부** 만족해야 한다.

1. 공-발 2D 거리 ≤ 200px (기존 `detect_touches_by_ball_direction` 조건)
2. ±8프레임 윈도우가 영상 범위 안에 완전히 들어옴
3. 윈도우 내 모든 프레임에 pose 랜드마크 존재 (visibility ≥ 0.5)
4. 윈도우 내 SAM2 공 추적 끊김 없음

판정 결과의 사용 방식:

- 유효 터치로만 헤드업·어깨-골반을 계산한다.
- **영상을 통째로 버리지 않는다.** `touch_quality = 유효 터치 수 / 전체 터치 수`를
  플래그로 함께 출력한다.
- 유효 터치가 **1개 이하면 계산이 불가능**하므로 그 지표만 `N/A`로 둔다.
  (헤드업은 터치별 range의 평균, 어깨-골반은 터치 구간 진폭이라 최소 2개가 필요하다.)
- 상체각도는 전체 프레임 기반이므로 터치 필터와 무관하게 항상 산출된다.

## 7. 실행 단계

### Phase 1 — 신호원 전환 (게이트, 반드시 먼저)

어깨-골반 신호원을 z축에서 2D 폭으로 교체하고, 아래를 출력한 뒤 **멈춘다.**

```
영상 13편 각각의 어깨-골반 교차상관 최대값
그 평균값
```

- **평균 상관 < 0.9** → Phase 2로 진행
- **평균 상관 ≥ 0.9** → **진행하지 말고 보고한다.** 이 동작에서 몸통 분리가
  관측되지 않는다는 뜻이므로 어깨-골반 지표 자체를 재검토해야 한다.

### Phase 2 — 채점 구현

§4의 공통 점수식과 §5의 지표 정의를 구현한다. `calibration.json`을 먼저 만들고
(`기준1`, `기준2`에서 `opt` 산출, 13편에서 `TAU = 2σ` 산출),
`score_video.py`가 영상 1편을 받아 점수를 내도록 한다.

### Phase 3 — 검증 (생략 금지)

`validate_scoring.py`로 아래를 출력한다.

1. 영상 13편의 `점수대 / 원시값 3개 / 점수 3개 / 총점 / 터치품질 / 플래그수` 표 (점수대 오름차순)
2. 세 지표 각각의 점수와 점수대의 **Pearson·Spearman 상관**
3. 하(3,5) / 중(6,7) / 상(8,9) 3그룹 평균과 **단조성 여부**

**상관이 낮게 나와도 파라미터를 튜닝하지 않는다.** 있는 그대로 보고하고
어떤 영상이 어긋나는지 짚는다. n=11이라 과적합이 너무 쉽다.
값을 바꿨다면 왜 바꿨는지 **물리적 근거**를 댄다.

### Phase 4 — 총점 가중치 배정

Phase 3에서 측정한 세 지표의 라벨 상관을 근거로 가중치를 배정한다.

- 가중치는 **`0.5 / 0.3 / 0.2` 세 고정값 중 하나**를 `|Spearman ρ|` 순위대로 배정한다.
- 라벨에 맞춰 연속값을 fitting하지 않는다. n=11에서 3개 가중치 학습은 확실한 과적합이고,
  근거 문서의 「튜닝 금지」 조항과 정면으로 충돌한다.
- 배정 근거를 코드 주석과 최종 보고에 남긴다.
- ρ가 음수로 나온 지표가 있으면 (앵커식이므로 정상이라면 양수여야 한다) 이를
  **문제로 보고하고** 가중치 최하위(0.2)를 준다.

헤드업이 `N/A`인 영상은 남은 두 지표의 가중치를 재정규화하고
총점에 `부분산출` 플래그를 붙인다.

### Phase 5 — 파노라마 비교 그림

`make_panorama.py`가 `output/figures/panorama_comparison.png`를 만든다.

**대상 영상 3편** (Phase 3 결과에서 자동 선택):

| 행 | 선택 규칙 | 현재 예상 |
|---|---|---|
| 1 | 레퍼런스 | `기준1` |
| 2 | 최고 점수대 중 총점이 가장 높은 영상 | `9-1` 또는 `9-2` |
| 3 | 최저 점수대 중 총점이 가장 낮은 영상 | `3-1` |

**레이아웃**

```
┌──────────────────────────────────────────────┬────────────┐
│ 기준1 (레퍼런스)                              │ 헤드업 10.0│
│  [f1] [f2] [f3] [f4] [f5] [f6]               │ 상체  10.0 │
│                                              │ 회전  10.0 │
│                                              │ 총점  10.0 │
├──────────────────────────────────────────────┼────────────┤
│ 9-1 (높은 점수)                               │ ...        │
├──────────────────────────────────────────────┼────────────┤
│ 3-1 (낮은 점수)                               │ ...        │
└──────────────────────────────────────────────┴────────────┘
```

**프레임 선택**: 영상 전체를 6등분한 등간격 6프레임.

점수는 터치 윈도우 기준으로 산출되지만 표시 프레임은 전체 등간격이므로,
그림 캡션에 **"프레임은 영상 전체 등간격, 점수는 터치 윈도우 기준 산출"** 을
명시해서 오해를 막는다.

**프레임 오버레이** — 숫자 없이도 차이가 보이게 세 지표를 직접 그린다.

| 지표 | 오버레이 | 낮은 점수에서 보일 차이 |
|---|---|---|
| 헤드업 | 어깨중앙 → 눈중앙 노란 화살표 + 각도 | 화살표가 계속 아래(공)를 향해 고정 |
| 상체각도 | 무릎-엉덩이-어깨 파란 호 + 각도 | 호가 펴져 있음 (상체를 세움) |
| 어깨-골반 | 어깨선 빨강 / 골반선 초록 2선분 | 두 선이 항상 나란함 (분리 없음) |

행 테두리 색으로 앵커 대비 편차를 표현한다. 기준1은 회색, 앵커와 유사할수록 초록,
차이가 클수록 빨강.

구현은 cv2로 프레임에 오버레이를 그리고 matplotlib으로 조립한다.
한글 폰트는 기존 스크립트와 동일하게 `AppleGothic`을 쓴다.

## 8. 출력 형식

CLI 출력:

```
인,인 7-2.MOV
──────────────────────────────
헤드업       7.2 / 10   (유효터치 5/6)
상체각도     8.1 / 10
어깨-골반    6.4 / 10   (ratio 0.74, opt 0.80)
──────────────────────────────
총점         7.2 / 10
⚠ 어깨-골반 비율은 3점대 판별에만 검증됨 (5~9점대 구분 불가)
```

같은 내용을 JSON으로도 저장해 `validate_scoring.py`가 배치로 읽을 수 있게 한다.
JSON에는 점수뿐 아니라 **원시값과 터치 품질, 경고 플래그**를 모두 담는다.
점수만 남기면 나중에 왜 그 점수가 나왔는지 되짚을 수 없다.

## 9. 한계 — 최종 보고에 반드시 포함

- **n=11** (기준 2편 제외). 5점대·6점대는 각 1편뿐이라 통계적 검증이 불가능하다.
- **어깨-골반 비율은 하위 판별(3점대 분리)에만 유효하다.** 5~9점대는 0.60~0.85에
  뭉쳐 있어 상위 구분을 못 한다.
- **어떤 정의도 하/중/상 단조성을 만족하지 못했다.** 8점대가 계속 골짜기로 나온다.
- 앵커 `opt`가 기준영상 2편에만 의존한다. 기준영상이 바뀌면 전체 점수가 바뀐다.
- 헤드업·상체각도는 아직 라벨 상관이 측정된 적이 없다. Phase 3에서 처음 측정된다.
  상관이 없게 나올 가능성을 배제할 수 없다.
