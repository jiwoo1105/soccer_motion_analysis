## 배경

축구 드리블(인-인) 영상에서 MediaPipe로 어깨·골반 회전을 측정해 0~10점을 매기는 파이프라인이다.
`input/in_in/` 에 영상 13편이 있고, **파일명 앞자리가 사람이 매긴 평가 점수대**다
(`인,인 7-2.MOV` → 7점대). `기준1`, `기준2`는 정답 템플릿 영상이다.

선행 분석에서 확정된 사실이다. **다시 검증하지 말고 전제로 받아들여라.**

1. **이상치(스파이크) 판별은 Hampel로 확정.** 전후 ±5프레임 중앙값 대비 10° 초과 시 이상치.
   `compare_spike_methods.py`의 `detect_spikes_hampel`이 채택본이다.
   - avg(이전 5프레임 평균)는 **정상 프레임의 28~40%를 오탐**해서 기각됐다. 쓰지 마라.
   - lastvalid는 피드백 래치로 점수가 최대 72% 붕괴해서 기각됐다. 쓰지 마라.
   - old(직전 프레임 차분)는 지속형 스파이크를 놓쳐 점수를 부풀린다. 쓰지 마라.
2. **어깨 진폭 단독은 점수대와 무관하다** (Pearson −0.21). 단독 지표로 쓰지 마라.
3. **어깨와 골반은 상관 0.89~0.99, 위상차 0프레임 — 사실상 같은 신호다.**
   두 값을 따로 점수화하면 중복이다. 관계 지표로 통합해야 한다.
4. **위상차(교차상관 lag)는 쓰지 마라.** Spearman +0.91이 나오지만 11개 중 8개가 동점인
   통계적 착시다. Pearson은 +0.17이다.

## 작업

### Phase 1 — 신호원 전환 (게이트, 반드시 먼저)

현재 회전각은 `atan2(vz, vx)`로 **MediaPipe world landmark의 z축**을 쓴다.
z는 촬영 각도에 따라 눌리는 것으로 확인됐다(8점대 두 영상이 어깨·골반 모두 최저권).
**2D 어깨/골반 폭 기반으로 교체하라.**

- `analyze_score_tiers.py`의 `extract_all()`에 이미 `sh_w2d`, `pe_w2d`
  (`abs(il[12].x - il[11].x) * w_frame`) 추출 코드가 있다. 이를 재사용하라.
- 2D 폭 → 회전각 변환식을 정하고, 근거를 주석으로 남겨라.
  (폭이 최대일 때 정면 0°, 좁아질수록 회전이 크다는 관계)
- 파이프라인 순서는 유지: `각도 → unwrap → Hampel 이상치 제거 → 선형 보간 →
  savgol(41,2) → 드리프트 제거(savgol 81,2) → find_peaks(distance=10, prominence=3)`
- **순서 중요**: 이상치 제거를 드리프트 제거보다 **먼저** 해야 한다.
  스파이크가 남은 채로 baseline을 뽑으면 주변까지 오염된다.

**Phase 1 완료 조건 — 아래를 출력하고 멈춰라:**

```
영상 13편 각각의 어깨-골반 교차상관 최대값
그 평균값
```

- **평균 상관 < 0.9** → Phase 2로 진행
- **평균 상관 ≥ 0.9** → **진행하지 말고 보고하라.** 이 동작에서 몸통 분리가
  관측되지 않는다는 뜻이므로, 어깨-골반 지표 자체를 재검토해야 한다.

### Phase 2 — 채점 구현

**측정 구간**: 영상 전체가 아니라 **공 터치 ±8프레임 윈도우**로 자를 것.
`analysis/head_pose_analyzer.py`가 이미 같은 방식을 쓰고 있다(`window=8`). 그 설계를 따르라.

**지표**: 어깨/골반 진폭 비율 `ratio = 어깨진폭 / 골반진폭`

물리적 의미 — 비율이 1.0에 가깝거나 넘으면 어깨가 골반만큼 돌았다는 뜻이고,
이는 상체로 몸을 끌고 가는 것(골반 주도 실패)이다. 3점대 영상 2편만 비율 ≥ 1.0이었다.

**점수 매핑** — 기존 헤드업 점수와 같은 형태로:

```python
# ratio_opt = 기준1·기준2의 비율 평균 (하드코딩하지 말고 기준영상에서 계산할 것)
# TAU_R    = 허용 편차. 초기값 0.40에서 시작하되, 검증 결과로 조정
score = max(0.0, min(10.0, (TAU_R - abs(ratio - ratio_opt)) / TAU_R * 10))
```

**Hampel 적용 시 두 가지 보강:**

```python
# ① 경계효과 제거 — 창이 잘리는 앞뒤 5프레임은 판정에서 제외
bad[:5] = False
bad[-5:] = False

# ② Hampel 한계 초과 경고 — 창 11개 중 과반(6개)이 오염되면 중앙값이 넘어가 놓친다
#    6프레임 이상 연속 플래그 구간이 있으면 경고를 출력할 것
```

### Phase 3 — 검증 (필수, 생략 금지)

**점수식을 만들었다고 끝이 아니다.** 아래를 출력하라:

1. 영상 13편의 `점수대 / 비율 / 점수 / 플래그수` 표 (점수대 오름차순)
2. 점수와 점수대의 **Pearson·Spearman 상관**
3. 하(3,5) / 중(6,7) / 상(8,9) 3그룹 평균과 **단조성 여부**

**상관이 낮게 나오면 숫자를 맞추려고 파라미터를 튜닝하지 마라.**
있는 그대로 보고하고, 어떤 영상이 어긋나는지 짚어라. n=11이라 과적합이 너무 쉽다.

## 반드시 지킬 것

- **결과를 좋게 보이려고 파라미터를 맞추지 마라.** τ, window, prominence를 상관계수가
  올라갈 때까지 돌리는 것은 n=11에서 무의미한 과적합이다. 값을 바꿨다면 **왜 바꿨는지 물리적
  근거**를 대라.
- **기존 파일을 덮어쓰지 마라.** `compare_spike_methods.py`, `extract_rotation_score.py`,
  `analyze_score_tiers.py`는 분석 근거 자료다. 새 모듈로 작성하라.
- **한계를 숨기지 마라.** 최종 보고에 반드시 포함할 것:
  - n=11, 5점대·6점대는 각 1편뿐이라 통계적 검증 불가
  - 비율 지표는 **하위 판별(3점대 분리)에만 유효**하고 5~9점대는 0.60~0.85에 뭉쳐 있어
    상위 구분을 못 한다
- 실행 환경: **`python3.9`를 쓸 것.** 다른 버전에는 mediapipe가 없다.
