# 이전 실행 경로에서 변경된 점

시작점은 `analyze_video.py`입니다. 기본 공 처리 경로를 원 연구와 같은 YOLOv8n+SAM2 (`sam2.1_hiera_small`)로 맞추고, 기존 YOLO11s 발목 ROI 경로는 선택 가능한 대안으로 구분합니다. 논문의 검출기를 YOLO11s로 바꾸지 않습니다. 실행 시 기존 `main.py`, `evaluate.py`, `extract_pose.py`와 실험용 스크립트를 혼용하지 않습니다.

| 이전 공개 경로 | 현재 경로 |
|---|---|
| 관절 추출, 공 재검출, 평가를 각각 실행 | 원본 영상부터 `analyze_video.py` 한 번으로 처리 |
| 추출과 공 검출에 서로 다른 Python 환경 사용 | Python 3.11 환경 하나 |
| 독립 CLI의 YOLO11s 발목 ROI 검출 | YOLOv8n+SAM2가 기본, YOLO11 ROI는 별도 대안 |
| 2D 어깨/골반 상대 정렬 변화량 | 어깨 벡터의 3D 방향 변화 속도를 SAM2 터치 중심 ±30 원본 프레임에서 평균 |
| 머리 각도 ±8프레임 범위 | 기존 후보 품질 조건 + 머리 각도 ±16프레임 범위 |
| 기준값에서 양방향으로 멀어지면 헤드업 감점 | 범위가 커질수록 증가하는 고정된 3~10 상대 환산 |
| 상체 원시각의 기준 근접도 환산 | 좌우 평균각은 유지, 보각 비율로 환산 |
| 세 항목 동일 비중 | 헤드업/상체/어깨 10/80/10 기본값, 명시적 변경 지원 |
| 기존 캐시/manifest를 준비한 뒤 실행 | 새 영상에서 좌표와 공 후보를 직접 생성 |
| 과거 실험 표 중심 | 실제 프레임 파노라마 + HTML + JSON |

## 2026-10-11 터치 창 변경

프로필 버전은 `2026-10-11-sam2-touch-window`입니다. 직전 CLI의 영상 전체 어깨 평균에서 다음과 같이 바뀝니다. **원래 SAM2 함수, 터치 자료에서 ±30을 탐색적으로 선택했습니다.** 상세 수식과 출처는 [계산 방법](methods.md)을 참고합니다. [논문](paper-touch-window.md)은 원래 검출, 헤드업, 상체 정의를 유지하고 어깨 집계와 터치 의존 관계를 반영합니다.

| 구분 | 새 계약 |
|---|---|
| 어깨 순간 속도 | 정규화한 `world[12]−world[11]`의 SG13, 2차 평활화와 3D 방향각 차이×FPS 유지 |
| 어깨 평균 범위 | 양 끝점이 같은 터치 중심 ±30 창에 속하는 유효 원본 이웃 쌍의 합집합; 영상 경계의 부분 창도 지원되는 쌍만 사용 |
| 겹침, 결측 | 같은 쌍은 한 번만 집계하고, 결측, 제외 프레임을 건너뛰어 연결하지 않음 |
| 터치 후보 | 기본 경로의 SAM2 터치 중심과 원래 공 품질 규칙 사용; 어깨 선정은 머리, 눈 품질과 독립 |
| 계산 불가 | 유효 터치 또는 창 안의 유효 어깨 쌍이 없으면 어깨와 총점 N/A; 영상 전체 평균으로 대체하지 않음 |
| 어깨 기준 속도 | 원래 SAM2 자료의 10점 기준 두 편에 같은 ±30 창을 적용한 평균 95.06803615376751°/s |
| 유지 항목 | 헤드업 ±16 원본 범위와 `3+7×clip` 환산, 좌우 무릎–엉덩이–어깨 평균, 기본 비중 10/80/10 |

헤드업의 원시 ±16 각도 범위는 SAM2 중심으로 다시 구하지만, `3+7×clip`과 기존 경계 10.225053625082124°, 15.30499039887986°는 고정합니다. 이 경계는 과거 ROI 탐색의 운영값이며 새 SAM2 자료로 다시 맞추거나 검증한 보정값이 아닙니다. 중심 ±8의 연속 SAM2 공 좌표, ±16 전체의 머리 품질, 최소 이벤트 2개 조건을 적용합니다. 상체 기준 보각 36.4628217436476°와 비중 0.1/0.8/0.1도 유지합니다. 어깨 `B_sh=30`은 헤드업 `Δ=16`, 평활화 `W_s=13`, `p_s=2`와 구별합니다. [아키텍처](images/paper-touch-window-architecture.png)와 [창 예시](images/touch-window-example.png)는 출처, 창 크기와 함께 읽어야 합니다.

전체 설정 파일은 schema 2이며 `measurement.shoulder`에 `aggregation: "touch_window_mean"`, `window_halfwidth_frames: 30`을 명시합니다. 이전 schema 1 전체 프로필이나 ROI의 ±24, 98.88202612670571°/s를 SAM2 프로필로 그대로 해석하지 않습니다. 측정 프로필과 공 처리 백엔드, 좌표, 공 후보 캐시의 버전도 구분합니다.

CLI의 기본 선택은 `--ball-backend yolov8_sam2`입니다. `--model` 기본값은 `models/yolov8n.pt`, `--sam2-checkpoint` 기본값은 `sam2_checkpoints/sam2.1_hiera_small.pt`이며 다른 로컬 경로를 지정할 수 있습니다. SAM2 추가 의존성과 체크포인트는 별도로 준비해야 합니다. `--ball-backend yolo11_roi`는 선택적 대안이며 원래 논문의 공 추적 방식과 별개입니다. 모델이 없을 때 대안 경로로 자동 전환하지 않습니다.

여섯 반폭 `N=6, 10, 16, 20, 24, 30` 중 SAM2 원자료에서 ±30을 선택했습니다. **어깨 원시 평균속도와 전체 드리블 등급의 상관**은 11편 ρ=0.602339, 10점 기준 두 편을 제외한 9편 ρ=0.271225입니다. 총점 상관이 아닙니다. 과거 ROI ±24 결과(0.56555, 0.20342)와 영상 전체 결과(0.56555, 0.271)는 별도 출처입니다. 이를 직접 비교해 개선을 주장하거나 독립 검증, 항목별 정답 검증으로 해석하지 않습니다.

원래 터치 검출기는 관측된 공 좌표만 모아 SG, 극값 탐지를 한 뒤 원본 프레임 번호를 복원하므로, 공 결측의 시간 간격을 압축하는 한계가 있습니다. 선택에 사용한 자동 후보에는 의심 이벤트도 포함됩니다. 모든 SAM2 터치가 실제 접촉 정답이라고 주장하지 않으며, 어깨의 원본 이웃 쌍 계산에서는 결측을 건너뛰지 않습니다.

## 기존 자료와 실행 기록

기존 예시 파노라마, HTML, JSON과 [검증 기록](validation.md)의 점수 및 테스트 횟수는 당시 버전의 기록입니다. 이를 새 창 방식의 재실행 결과로 바꾸어 읽지 않습니다. 캐시에서 다시 계산해도 측정 계약과 어깨 기준이 달라지므로 이전 보고서와 점수가 같을 필요는 없습니다.

이전 ±16 헤드업 표는 `calculate.py`의 ROI 이벤트에 기반하고, 이전 어깨 탐색도 `roi_head_results.json`을 재사용했습니다. 배치 메타데이터의 `yolo11s.pt` 출처를 원래 논문의 공 추적 방식으로 얻은 결과로 바꾸어 표기하지 않습니다. 새 경로는 SAM2 중심에 같은 머리 각도 정의와 원래 공, 헤드업 품질 규칙을 적용하되 과거 ROI 운영 경계를 고정해 사용합니다.

기존 캐시는 새 실행 경로에서 자동으로 읽지 않습니다. `--reuse-cache`는 새 실행이 만든 해시와 원본 시계 정보가 있는 번들만 대상으로 합니다. 기존 분석에서 수동으로 제외했던 특정 영상/프레임을 파일명에 따라 자동 제외하는 규칙은 배포 코드에 넣지 않았습니다.

SAM2 캐시는 `tracks.json`과 `ball_source: yolov8_sam2`를 사용합니다. 기존 `candidates.json` ROI 캐시는 `--ball-backend yolo11_roi`로만 재사용하며, 출처가 없는 예전 캐시도 SAM2로 간주하지 않습니다. 선택한 백엔드와 캐시 출처가 다르면 오류를 냅니다.

과거 분석 파일과 이미지의 중복된 실행 경로는 현재 Git 트리에서 정리했습니다. 필요한 관절/공 수치 함수, 추론 연결, 점수, 보고서, 설정, 테스트만 남겼습니다. 원본 영상이나 개인 실험 결과 폴더를 Git에 올리지 않았습니다.

이전 버전은 삭제 이전 커밋 [a6c6d3b](https://github.com/jiwoo1105/soccer_motion_analysis/tree/a6c6d3bccce787a5143cb3b793c822c987c08b4b)에서 볼 수 있습니다. 기존 로컬 분석 폴더와 캐시를 새로운 배포 작업으로 덮어쓰지 않았습니다.
