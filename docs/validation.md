# 실행 검증 기록

검증일: 2026-10-07. 이 문서는 프로그램의 실행 및 수치 처리 검증입니다. 전문가 등급 예측 정확도나 새로운 자료에 대한 외부 성능 검증을 의미하지 않습니다.

## 자동 테스트

Python 3.11의 새 가상환경에서 `python -m pytest -q` 실행 결과 **109개 통과**를 확인했습니다. 영상이나 모델이 필요 없는 검사입니다.

| 검사 | 확인 내용 |
|---|---|
| 원본 시계 | 관절 결측 프레임 유지, ROI 좌표를 원본으로 복원, 부분 디코드 중단 |
| 점수 | 알려진 회전의 속도, 좌우 상체 평균, ±16 머리 범위, 고정 환산값, 가중치 합 |
| 품질 | 관절 튐, visibility, 구간 경계, 결측을 넘는 프레임 쌍 제외, N/A 총점 |
| 캐시 | 원본/좌표/후보 해시, 원본 FPS와 캐시 시각, 해상도, ROI 불일치 차단 |
| 출력 | 기존 폴더 보호, 보고서 생성 중 원본 변경 시 게시 중단 및 임시 폴더 정리 |

| 모델 설치 | 공식 해시 확인, 불일치 모델 거부, 기존 파일 보호 |

## 실제 원본 영상 추론

캐시를 재사용하지 않고 영상 3편을 `analyze_video.py`에 함께 전달했습니다. 원본 총 **771프레임**에서 MediaPipe Heavy 관절 추출, YOLO11s 공 검출, 점수 계산, PNG/HTML/JSON 생성이 완료되었습니다. 실행 시간은 약 **336초**였습니다.

환경: Apple M4 Pro, macOS 26.5.2, Python 3.11.12. YOLO는 CPU 옵션으로 실행했습니다. MediaPipe 로그에는 Metal GL 컨텍스트와 XNNPACK 사용이 기록되었습니다. 패키지 버전은 `requirements-runtime.txt`와 각 보고서의 `video.versions`에 남깁니다.

| 영상 | 프레임 | 헤드업 원시값 / 점수 | 상체 원시값 / 점수 | 어깨 원시값 / 점수 | 총점 |
|---|---:|---:|---:|---:|---:|
| 인,인 기준1 | 239 | 15.305° / 10.00 | 143.594° / 9.98 | 93.979°/s / 10.00 | 9.99 |
| 인,인 7-2 | 292 | 14.748° / 9.23 | 149.765° / 8.29 | 82.366°/s / 8.76 | 8.43 |
| 인,인 3-1 | 240 | 11.037° / 4.12 | 151.401° / 7.84 | 84.564°/s / 9.00 | 7.59 |

비중은 헤드업/상체/어깨 10/80/10입니다. 계산은 반올림 전 값을 사용했습니다. 표와 파노라마에는 입력 이름만 표시하며 이름의 등급 숫자를 모델 입력이나 환산에 사용하지 않았습니다.

[예시 PNG](images/panorama-example.png), [예시 HTML](example-report.html), [반올림 전 값과 메타데이터](example-report.json)를 함께 제공합니다. 문서용 그림은 위 추론 결과의 해시를 검증한 캐시에서 다시 그렸고, 세 항목 점수가 최초 추론 결과와 1e−10 이내에서 같은지 검사했습니다. 원본 영상, 개인 경로, 관절 전체 캐시는 공개하지 않습니다.

**3-1도 총점 7.59로 높게 나왔습니다.** 실행 성공이 등급 구분 성공을 뜻하지 않습니다. 상체의 비중이 80%이며 3-1의 해당 항목 자체가 7.84점입니다. 이 결과를 실제 3등급과 잘 맞는다고 해석할 수 없습니다. 과거 표의 수동 프레임 제외를 영상 이름에 따라 자동 적용하지 않았으므로 어깨 값은 수동 검수 표와 다를 수 있습니다.

## 플랫폼 및 모델 검증

두 공식 모델을 새 가상환경에서 다운로드하고 체크섬을 확인했습니다. `scripts/setup_models.py --check`도 통과했습니다. 실제 입력 없이 결과 숫자를 채운 예시는 사용하지 않았습니다.

macOS ARM 환경에서는 `python -m pip check`가 MediaPipe 0.10.21의 휠 플랫폼 메타데이터에 대해 `is not supported on this platform` 경고를 냈습니다. 설치된 휠의 내부 태그는 x86_64였지만 네이티브 ARM Python에서 import, Heavy 모델 실행, 위 세 영상 추론은 성공했습니다. 이 경고가 없었다고 기록하거나 모든 플랫폼에서 같은 결과를 보장하지 않습니다. 실행 시 바이너리 import 오류가 발생하면 해당 OS의 Python 3.11/MediaPipe 지원을 확인해야 합니다.

GitHub Actions는 Ubuntu/Python 3.11에서 **모델 없는 자동 테스트**만 실행합니다. Linux/Windows의 실제 모델 추론이나 GPU별 수치 일치는 별도로 확인하지 않았습니다.
